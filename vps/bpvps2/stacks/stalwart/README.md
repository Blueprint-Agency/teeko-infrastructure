# Stalwart + Bulwark — self-hosted email for `blueprintdigital.my` (BPVPS2)

Replica of the proven `bpvps1` / `kaiteki.my` stack (`../../../bpvps1/stacks/stalwart/`),
co-hosted on BPVPS2 (`187.127.207.82`) alongside booking-system, behind the same Traefik.
**Stalwart** (Rust mail server) handles SMTP/IMAP/POP3/JMAP/ManageSieve + DKIM + spam;
**Bulwark** is the JMAP webmail.

| | URL | Login |
|---|---|---|
| Stalwart admin | `https://mail.blueprintdigital.my` (→ `/account`) | `admin@blueprintdigital.my` |
| Webmail | `https://webmail.blueprintdigital.my` | mailbox creds |
| Bulwark admin dashboard | `https://webmail.blueprintdigital.my/admin` | `BULWARK_ADMIN_PASSWORD` (stack `.env`) |

Stack dir on VPS: `/root/stacks/stalwart/`. Mail data in the `stalwart-data` volume
(RocksDB at `/opt/stalwart/data`).

> ⚠️ The apex `blueprintdigital.my` points at **Vercel** (`64.29.17.1`, `216.198.79.1`).
> This stack only adds the `mail.` / `webmail.` subdomains and the zone's MX/SPF/DKIM/DMARC.
> **Do not touch the apex A records.**

## How it fits together
Identical to bpvps1 — see that README for the full rationale. Summary:
- **Mail ports** (25/465/993/995/4190) bind directly on the host. Only implicit-TLS ports
  are published; Stalwart has no 587/143/110 listener (add one in the admin UI *first* if
  a client ever needs STARTTLS submission).
- **Web UIs** go through Traefik: `mail.` → `stalwart:8080`, `webmail.` → `bulwark:3000`,
  over the external `stalwart_mailnet` network. See `../traefik/dynamic/stalwart.yml`.
- **Bulwark → Stalwart is JMAP over HTTPS**, following the absolute URLs in Stalwart's JMAP
  session, so Stalwart's **Default Hostname must be `mail.blueprintdigital.my`**, and that
  name is a **network alias on Traefik** so it resolves internally with a valid cert.
- **Traefik owns CORS** for the mail host (`mail-cors` middleware); Stalwart's own
  "Permissive CORS" stays **OFF**.
- Stalwart must trust the proxy: **Settings → Network → HTTP Server → "Obtain remote IP from
  Forwarded header" = ON**, plus **Settings → Security → Allowed IPs → `172.16.0.0/16`**,
  or a bot scan for a banned path bans Traefik and every mail web UI 502s.

## TLS
One LE cert for `mail.` + `webmail.blueprintdigital.my`, issued **out-of-band via Cloudflare
DNS-01** (acme.sh + `BPD_CF_DNS_API_TOKEN`) because Traefik's CF token only covers `teeko.ai`.
Cert lands in `./certs/{fullchain,key}.pem`; Traefik serves it via the file provider and
Stalwart reads the same files (admin UI → Settings → TLS, as **File** references).
⚠️ `chown 2000:2000 ./certs/*.pem` or Stalwart can't read them.
Renewal: `renew-cert.sh` (daily host cron). Cert is **ECC**, acme dir `./acme/mail.blueprintdigital.my_ecc/`.

## DNS (zone `blueprintdigital.my`, Cloudflare — needs `BPD_CF_DNS_API_TOKEN`)
| Record | Name | Value |
|--------|------|-------|
| A | `mail.blueprintdigital.my` / `webmail.blueprintdigital.my` | `187.127.207.82` (DNS-only, grey cloud) |
| MX | `blueprintdigital.my` | `mail.blueprintdigital.my` (10) |
| TXT (SPF) | `blueprintdigital.my` | `v=spf1 mx -all` |
| TXT (DKIM) | `<selector>._domainkey` | generated by Stalwart after the domain is added |
| TXT (DMARC) | `_dmarc.blueprintdigital.my` | `v=DMARC1; p=reject; rua=mailto:admin@blueprintdigital.my; fo=1` |

PTR (Hostinger hPanel): `187.127.207.82` → **`mail.blueprintdigital.my`** (FCrDNS / deliverability).

> Same anti-spoof posture as kaiteki.my: SPF `-all` + DMARC `p=reject`. `mx` (this VPS) is the
> only authorized sender. **If you add a 3rd-party sender (CRM, marketing, Vercel forms), add
> its `include:` to SPF _before_ it sends**, or DMARC will reject it.

## Firewall (Hostinger hPanel, BPVPS2)
Existing 22/80/443 plus: **25, 465, 993, 995, 4190**.

## First boot (already done 2026-08-06 — here for the next host)
Because `config.json` is bind-mounted from the start, Stalwart's entrypoint skips its
installer — which is also what normally creates the data dir. A fresh named volume is
root-owned, but Stalwart runs as **uid 2000**, so it crashloops with
`Failed to create database directory /opt/stalwart/data: PermissionDenied`. Fix once:
```bash
docker compose stop stalwart
docker run --rm -v stalwart_stalwart-data:/d alpine chown 2000:2000 /d
docker compose up -d stalwart
```

## ⚠️ Gotchas / landmines
Same set as bpvps1 — most importantly:
- **A fresh `stalwart-data` volume must be `chown 2000:2000`** — see First boot above.
- **`config.json` is persistence-critical** (bind-mounted storage pointer). Without it a
  container recreate wipes Stalwart back into the setup wizard.
- **Most config lives in the store**, set via the admin UI; the v1.0 management REST API is
  OAuth-only, so there's no easy scripting.
- ⚠️ **fail2ban behind a reverse proxy** — see the XFF / Allowed-IPs settings above.
- Port 25 outbound is **open** on this host (verified 2026-08-06).
