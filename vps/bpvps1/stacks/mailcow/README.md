# Mailcow — self-hosted email for `kaiteki.my` (co-hosted on BPVPS1)

Dockerized Mailcow providing mail + admin UI for **kaiteki.my**. The admin/management
UI **and** the mail server hostname are both **`email.kaiteki.my`**. The client creates
and manages mailboxes/quotas themselves in the Mailcow UI.

> **Co-hosted, not standalone.** Mailcow runs on **BPVPS1** (`bp-bpvps1`, `187.127.122.41`)
> alongside the existing Traefik + `kaiteki` site + `wordpress` blog. Mailcow is **not**
> vendored in this repo — it lives at `/opt/mailcow-dockerized` (upstream
> `mailcow/mailcow-dockerized`). This dir documents the integration + overrides only.
> Secrets live in `/opt/mailcow-dockerized/mailcow.conf` on the VPS (never committed).

## Why co-hosted behind Traefik

Traefik already owns ports 80/443 on BPVPS1, and its Cloudflare token only covers the
`teeko.ai` zone — it **cannot** DNS-01 a cert for `kaiteki.my` (a separate Cloudflare
account). So:

- **Mailcow self-issues its own Let's Encrypt cert via HTTP-01** (`SKIP_LETS_ENCRYPT=n`),
  keeping its native cert lifecycle for nginx + Postfix + Dovecot.
- **Traefik just routes** `email.kaiteki.my`: `:80` forwards to Mailcow nginx (so the
  ACME challenge is reachable + http→https redirect), `:443` is **TLS-passthrough** so
  Mailcow serves its own cert. See `../traefik/dynamic/mailcow.yml`.
- Mail ports (25/465/587/993/995/143/110/4190) bind directly on the host — no Traefik.

`email.kaiteki.my` must be **DNS-only (grey cloud)** — mail can't be Cloudflare-proxied.

## `mailcow.conf` overrides (applied after `generate_config.sh`)

```ini
MAILCOW_HOSTNAME=email.kaiteki.my
TZ=Asia/Kuala_Lumpur
# Reverse-proxy mode: bind nginx to loopback alt-ports so Traefik keeps 80/443
HTTP_BIND=127.0.0.1
HTTP_PORT=8080
HTTPS_BIND=127.0.0.1
HTTPS_PORT=8443
SKIP_LETS_ENCRYPT=n      # Mailcow self-issues via HTTP-01 (Traefik forwards :80)
SKIP_CLAMD=y             # trimmed to fit 2 vCPU / 8 GB beside the web stack
```

Traefik also joins the `mailcowdockerized_mailcow-network` (external) to reach
`nginx-mailcow:8080` / `:8443`.

## DNS (zone `kaiteki.my`, separate CF account — `KAITEKI_CF_DNS_API_TOKEN`)

| Record | Name | Value |
|--------|------|-------|
| A | `email.kaiteki.my` | `187.127.122.41` (DNS-only) |
| MX | `kaiteki.my` | `email.kaiteki.my` (prio 10) |
| TXT (SPF) | `kaiteki.my` | `v=spf1 mx ~all` *(tighten to `-all` after testing)* |
| TXT (DKIM) | `dkim._domainkey.kaiteki.my` | selector `dkim`, 2048-bit (generated by Mailcow) |
| TXT (DMARC) | `_dmarc.kaiteki.my` | `v=DMARC1; p=none; rua=mailto:dmarc@kaiteki.my; fo=1` |
| CNAME | `autodiscover` / `autoconfig` | `email.kaiteki.my` |

Stale cPanel records (`webmail`, `cpcalendars`, old `autodiscover`/`autoconfig` A
records → `103.198.68.41`) and the old SPF were deleted during cutover.

## Host requirements (Hostinger hPanel — BPVPS1)

- **Firewall (inbound TCP):** `22, 25, 80, 443, 465, 587, 993, 995, 143, 110, 4190`
- **PTR / rDNS:** `187.127.122.41` → `email.kaiteki.my` (required for deliverability)
- **Outbound 25:** confirmed open.

## Admin / first-run

- Panel: `https://email.kaiteki.my` — default `admin` / `moohoo` → **change immediately**.
- `admin@kaiteki.my` mailbox created for the client; further mailboxes via the UI.

## Operations

```bash
cd /opt/mailcow-dockerized
docker compose ps
docker compose pull && docker compose up -d     # apply pulled updates
./update.sh                                      # upstream Mailcow update
```

> Not wired into `deploy-infra.yml` (BPVPS1 is outside infra CI). Managed manually.
